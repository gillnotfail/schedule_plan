# 2026-09-19 课表页默认表格 + Excel 导入崩溃修复

## 用户反馈的两件事

1. **课表页还是不显示默认表格**。反复强调：第一列是节次和对应时间，第一行是周几，
   点第一列能改某一节时间、后续课按默认课间自动顺延。
2. **导入 Excel 名单时崩溃**：`custom numFmtId starts at 164 but found a value of 41`。

## 问题 1 的根因与修法

### 根因（两条，都会让用户看到"没有表格"）

- 老版本建库的种子数据**没写出厂作息**；旧版「一键清空课表」又会把
  `template_period` 整段删掉 —— 这两类模板打开课表页时第一列全空、
  格子里只剩 `—`，看起来就是"没有课表表格"。
- 一个班级都没有时，`_buildBody` 直接 `return EmptyView(...)`，整张表都不渲染。

### 修法（三层兜底，缺一层就会复发）

1. `TemplateRepository.ensureFactorySchedule(templateId)`：整份作息为空时补一份出厂作息
   （事务内先 COUNT，>0 直接返回 false，不会覆盖用户调过的任何一天）。
   课表页 `_load()` 里调用，老库升级后自愈。
   为此把 `DatabaseSchema.insertDefaultPeriods` 的入参从 `Transaction` 放宽到
   `DatabaseExecutor`，事务内外都能调，仍然只有这一处算法。
2. 课表页不再要求「必须有班级」：没有班级时用**默认作息模板**渲染表格，
   上面只加一条可点击的提示条（→ 班级管理），FAB 会提示先建班级。
   `_ScheduleData` 新增 `templateId`（当前表格用的作息模板 id）。
3. `ClassGridView` 内部新增 `_periods` getter：模板作息整份为空时用出厂骨架渲染
   （纯内存，不落库）。同时把入参从 `classInfo` 换成 `templateId`，
   这样没有班级也能渲染同一张表。

### 顺带改掉的语义

- **「一键清空课表」只清 `lesson`，不再删 `template_period`**。
  作息是表格骨架，删掉就会得到一张连节次都没有的空表 —— 这正是用户看到的 bug。
  作息行的增删归作息模板编辑页。`clearScheduleConfirm` 中英文案同步改了。

### 新增/更新的测试

- `test/unit/database_repository_test.dart`：
  - 改建「新建模板自带同一份出厂作息」；
  - 新增「一键清空课表只清课表内容，作息必须保留」；
  - 新增「作息为空的模板会被自愈补齐（且不会重复补）」。
- `test/widget/schedule_grid_view_test.dart`（新）：第一行周一到周五、第一列节次+起止时间；
  以及「节次为空时也要渲染出厂骨架」。

## 问题 2 的根因与修法

`excel` 4.0.6 的 `lib/src/parser/parse.dart` 解析 `xl/styles.xml` 时，
对 `<numFmts>` 里任何 `numFmtId < 164` 的声明**直接 throw**：

```
custom numFmtId starts at 164 but found a value of 41
```

而 WPS / 老版 Excel / 部分报表系统导出时，会把内置数字格式（41/42/43/44 等）
又声明一遍。于是整份名单一个字都读不出来，还把英文技术异常直接甩给用户。

### 修法

新增 `lib/data/services/xlsx_repair.dart`：xlsx 就是 zip，拆包改掉 `xl/styles.xml` 再重打包。

- 声明侧 `<numFmt numFmtId="N">`：
  - `N >= 164` 合法，不动；
  - `N < 164` 且是 excel 包已支持的内置 id → **删掉冗余声明**（被它覆盖的 id 集合
    来自包内 `_standardNumFormats`，代码里写死了并注明出处）；
  - `N < 164` 且不受支持（41/42/43/44 这些）→ 改成 ≥164 的空闲 id，同步改写引用。
- 引用侧 `<xf numFmtId="N">`：重映射的改新 id；既没声明又不受支持的一律归零成
  General —— 这正是 excel 包在 release 下的兜底行为，区别只是不再让 debug 断言崩。
- 无需修改或修复失败返回 `null`，调用方按原样处理。

`ExcelService` 新增 `decodeWorkbook()`：先原样解析，失败才修一遍重试；
另新增 `ExcelParseException`，导入页 catch 到就给用户看新文案键
`importFileUnreadable`（技术细节只进日志）。**以后解析 Excel 统一走 `decodeWorkbook`。**

### 新增测试

`test/unit/xlsx_repair_test.dart`（新）：

- 用 `Excel.createExcel()` 造一份合法 xlsx，再把 styles.xml 换成带

## 踩坑

1. **`testWidgets` 体内不能 await 真实 I/O**。第一版 widget 测试在测试体里
   `await templates.listTemplates()`，FakeAsync 区里 sqflite 回调永远不触发，
   表现为 `pumpAndSettle` **10 分钟超时**。修法：DB 准备全放 `setUp`，测试体只 pump。
2. **PowerShell 工具会在 120s 掐掉命令**（`flutter test` 首次编译必超），
   所以 analyze/test/build 一律用 Bash 的 `run_in_background: true` + 文件重定向。
   另外 `[System.IO.File]::AppendAllText` 那套在 `& flutter` 调用下会被
   NativeCommandError 打断，回到最朴素写法最稳。
3. **并发跑两个 flutter 会撞 native assets**：
   `PathExistsException: Cannot copy file to 'build\native_assets\windows\sqlite3.dll'`。
   清 `build/native_assets` 重跑即可。`rm -rf` 会被 safe-delete 拦住，
   要用 PowerShell 的 `Remove-Item -Recurse -Force`。
4. `archive` 3.x 写条目是 `Archive.addFile()` 不是 `add()`（4.x 才改成 `add`）。
5. 老文件是 CRLF，按 `\n` 拼的锚点串匹配不上，脚本里要按换行符分别处理。

# 2026-09-19（下午）格子点击逻辑 + 展示状态冷存储

## 用户反馈

1. **「改了课表时间，退出重开第一列又变回默认」** —— 要求改后的时间必须冷存储。
2. 新交互：点课表格子 → 空格子引导建课 / 有课弹详情 + 去点名；
   点名要跳到「这节课所在周几最近的日期」。
3. 名单 / 班级 / 课程的增删确认与引导（新建班级提醒加名单、删班级二次确认等）。

## 关键结论：时间丢的不是数据，是「在看哪套作息」

先用临时测试证明 `template_period` **确实写进库了、重开也在**。
所以真 bug 在**课表页每次进入都重新推导展示模板**：
老逻辑是「选中班级的模板 → 否则 `is_default` 的模板 → 否则第一个」。
用户没有班级，且库里有不止一套模板时，重启就会静默换成另一套作息，
用户看到的现象就是"我改的时间又变回默认了"。

修法：把**展示状态本身落库**
（`SettingKeys.scheduleDisplayTemplateId` / `scheduleSelectedClassId`，默认值都是 '0'）。
优先级：无班级时以持久化模板为准；有班级时以班级绑定为准
（班级绑定才是"这节课几点上"的唯一真相）；两者都拿不到才回落到默认模板。
`_load()` 结束时把"这次真正展示的"再写回去。
另外右上角作息切换改成**模板数 > 1 就显示**，无班级时只切展示作息、不写班级绑定。

## 跨 Tab 跳转（不能 push）

课表 / 考勤是 `MainShell` 的 `IndexedStack` 平级子页，**没有 Navigator push 关系**。

`MainShell` 的选中 Tab 改为 `context.watch<AppNavigationState>().tabIndex`。
考勤页在 `didChangeDependencies` 里挂 listener，另加一个 post-frame 兜底调用。
定位用新加的 `DateUtils.nearestWeekdayDate(reference, weekday)`：
本周还没到就用本周（含今天），本周已过就顺延下周。

这跟"考勤要长期保存"直接冲突。SQLite 改不动已有外键的删除动作，只能整表重建

否则 `DROP TABLE` 会触发隐式级联）。

新表字段（`DatabaseSchema.version = 4`）：
| 字段 | 说明 |
|---|---|
| student_id | NOT NULL, FK student(id) ON DELETE CASCADE（人删了记录才该没） |
| lesson_id | **可空**，FK lesson(id) **ON DELETE SET NULL**（条目没了记录留下） |
| class_id / course_id | 可空 + SET NULL，班级/课程删除后置空 |
| date | "YYYY-MM-DD" |
| weekday / period_index | 节次定位快照 |
| start_time / end_time | 该节次起止时间快照 |
| course_name / class_name | 课程名/班级名快照 |
| status / note | 状态与备注 |
| recorded_at | **首次标记**时间戳（重复点名不动它） |
| updated_at | 最后一次改动时间戳 |
- 索引补了 `idx_attendance_student_date(student_id, date)` ——
  高风险检测是"逐生按时间范围统计"，原来每生一次全表扫描。
- 迁移时按 lesson/course/class/template_period **回填**所有快照列，
  并在 DROP 前**校验条数一致**（不一致就抛错回滚）。
- `AttendanceRepository.upsert` 从 `ConflictAlgorithm.replace`（删了重插，会把
  recorded_at 重置）改成 `INSERT ... ON CONFLICT(student_id, lesson_id, date)
  DO UPDATE`，只刷新 status/note/updated_at。
- 新增 `AttendanceRepository.mark({lesson, studentId, date, status})`：
  点名路径上唯一该用的写法，快照由 `AttendanceRecord.forLesson` 一次取齐。
- `exportSummary` / `abnormalDetails` / `attendanceRateByCourse` /
  `weeklyAbsenceCountByClass` 全部改成 LEFT JOIN + `COALESCE(a.xxx, l.xxx)`，
  孤儿记录也读得出课程名、班级名、时间。

### 经验
- 测试里 `find.byIcon(Icons.add)` 的下标要注意：被课程占掉的格子没有 add 图标
  （周一第 1 节有课时，`.at(0)` 就已经是周二了）。
- `pumpAndSettle` 会把 `Future.delayed` 一起推完，所以想观察"展开中"的状态必须用
  `pump()` + `pump(Duration(...))` 分段推，不能直接 settle。
- 对话框里用到了 `ThemeController`，widget 测试的宿主必须自己挂
  `ChangeNotifierProvider<ThemeController>.value`（真实 App 里它在 MaterialApp 之上）。

- `flutter build apk --release` → **app-release.apk 61.9MB**（64882675 字节，22:03）。
  三方 ABI 分包：arm64 21.9MB / armeabi-v7a 19.8MB / x86_64 25.1MB。
