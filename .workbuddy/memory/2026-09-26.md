- **采纳「联网 + 本地缓存 + 内置兜底」**。

### B. 分差升级：算法层

**为什么不能定长分块**：APK 里 `lib/libapp.so`（Dart AOT 快照，8~12 MB）改几行代码就**整体位移**，
定长 4 KB 一刀会全面失配，补丁≈整包。→ 用 **CDC（内容定义分块）**：32 位 **gear 哈希**
`h = (h << 1) + GEAR[b]` 滚动，`h & MASK == 0` 处切一刀；边界只取决于**内容**、与偏移无关。

三个关键性质（都是实测撞出来的）：

1. **掩码必须取高 15 位（bits 17..31）**。gear 哈希的 `bit0` **恒等于 `GEAR[最后一个字节] & 1`**，
   低位只有 256 种取值 → 掩码放低位会退化，`bits 1..29` 那版曾出现"整份目标文件切不出边界"。
   实测候选后选 `17..31`（APK 均值 39806 B）。`selftest` 加了**均值必须落在 `[1<<14, 1<<16]`** 的护栏。
2. **纯常量串会收敛到不动点**：零串 → `-GEAR[0] = 0xA7825A60`，0xFF 串 → `0x2472BC90`，都与掩码不相与
   → 长零填充稳定切成 `MAX_CHUNK` 块，不会碎成 4 KB 灾难。副产品：**撞上限的块长度与内容无关**
   → **边界不因内容改动而漂移**（这才是"改 1 字节仍复用 99.9%"的机制）。
   ⚠️ 写用例别用"整份都是零"，要用**数据块与零填充交替**（模拟可执行文件）。
3. `MAX_CHUNK` 从 128K 降到 **64K**：实测 128K/64K/32K 补丁大小几乎无差别，但上限越小，
   "长常量串中间被改动"时作废的边界块字节越少。`chunk_index` 必须**保留全部位置（含末尾残块）**，
   否则命中率明显下降。

补丁格式 **SPDP v1**：整体 gzip，解压后固定头 98 字节 + 命令表 + 字面量。命令只两种：
`COPY_BASE(offset u64, length u32)` 13 字节、`COPY_LITERAL(length u32)` 5 字节。
命中候选**逐字节复核**防哈希碰撞。

**分块只在生成端（Python），设备端纯 Dart 只做"校验指纹 → 按命令搬字节 → 校验产物指纹"**
→ 不存在"两端分块边界必须一致"的跨语言陷阱，只需格式解析一致（`test/fixtures/delta/` 固定样例锁住）。

### B. 分差升级：应用链路

- **三层安全网**：① 下载后按清单 `sha256` 校验；② 分差合成后再校验产物指纹；
  ③ 再与**清单里整包的指纹交叉校验**（两个独立来源）。任一步失败 → 删文件 → 换下一地址 →
  **最终回落下载完整包**。生成端 `--verify` 自校验，合不出来就中止发布，不发出去。
- **清单地址**：raw.githubusercontent 第一、jsDelivr 第二、再乘用户可配镜像前缀。**自动检查一天一次**。
- **安装走 `PackageInstaller`，不是 `ACTION_VIEW` + FileProvider**。决定性理由：
  本项目 **`androidx.core` 是由 `share_plus` 以 `compileOnly` 引进来的**，
  自建一个 FileProvider 子类会因为类不在本模块 classpath 上而**编译不过**。
  `PackageInstaller` 把字节写进安装会话管道，不需要 content URI，还能拿安装结果回执。
  要 `REQUEST_INSTALL_PACKAGES` 权限 + `canRequestPackageInstalls()` + 跳「安装未知应用」授权页。
- **`InstallResultReceiver` 会被调用一到两次**；系统装完会重启进程 → 回执可能送不到
  → 加了 `markInstalledExternally()`（回前台比对版本号兜底）。

### D. `release.py` 补强（打包前先验 token）

用户给的 token **只有 31 个字符**（字面内容已移除，见 `2026-09-27.md` 的说明）。
细粒度 PAT 形如 `github_pat_<22 位>_<59 位>`，**共 93 字符、中间还有一个下划线** ——
用户复制时被截断了。服务端只回一句 `401 Bad credentials`，很容易误判成权限问题。

由此改了四处：

1. **token 校验提到打包之前**（`verify_token`：`GET /user` + `GET /repos/...`
   并检查 `permissions.push`）。原先 token 是构建完、清单写完、产物缓存完才用，
   坏 token 会白等一轮几分钟构建，还留下改了一半的工作区。
2. **截断自检** `token_looks_truncated()`：`github_pat_` < 80 字符、
   `ghp_/gho_/ghu_/ghs_` < 36、其他 < 20 就判定截断，直接说明长度不对。
3. **token 可读 `~/.schedule_plan-release.env`**（dotenv 风格，环境变量优先）。
   **故意放家目录不放仓库**：仓库里任何文件都有被 `git add -A` 带上去的风险，
   PAT 泄露不可逆；而发版要反复执行，每次明文写命令行会落进 shell 历史。
4. `commit_and_tag` 改**幂等**（标签已存在且 `rev-parse tag^{}` == HEAD 就跳过）：
   否则"上传成功、推送失败"这种半途而废的重跑会死在"标签已存在"上。

顺带修掉：版本提示里的 `%d` 没插值；末行日志在跳过上传时谎称"确认附件已上传"。
