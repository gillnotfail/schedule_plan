
## 第 36 轮：学生/班级信息改了，考勤页名单要实时（v1.0.15）

**用户报告**：*"如果教师在开头导入学生名单后，如果修改部分学生信息，对应到课表页-去点名-跳转考勤页，
这个学生信息是没有修改的……常见的修改包括但不限于：修改部分学生姓名、班级、性别等信息；删除、新增学生等。"*

**查到的事实**（写下来免得下次重查）：
- 考勤名单走 `StudentRepository.listByClasses`，**每次都是实时查库**；`_loadStudents` 在
  「去点名」「切日期」「换课」「切回 Tab」四条路上都会被调用 —— 所以**姓名/学号/增删本身是会刷新的**，
  widget 测试已锁死（`test/widget/attendance_roster_refresh_test.dart` 4 条）。
- **真正复现出来的 bug**：`_refreshHolidayContext`（切 Tab 回来那条路）**没有 `_loadClasses()`**，
  而 `_classNames`/`_classOrder` 只在 `initState` 读一次 → **改班名永远不生效、新建的班连名字都没有**
  （分组横带回落成「班级管理」）。去掉 `_loadClasses()` 能让 `班级改名后…` 那条用例稳定失败，加回来通过。
- 顺带修：首次 `_loadAll` 与「去点名」撞车时，先发起的那次后返回会覆盖/清空名单（加 `_lessonToken`/
  `_studentToken` 世代号丢弃旧返回）。
- `AttendancePage` 加可注入 `HolidayService`：不注入时默认实例走 `SettingsRepository()` →
  `AppDatabase.instance()`，widget 测试里会把 pump 挂住（上一版测试卡 8 分钟就是这么来的）。

**测试**：`test/widget/attendance_roster_refresh_test.dart` 5 条（去点名改名/改学号/转班、新增/删除、
切 Tab 回来、班级改名、首屏未加载完就点去点名）。全量 **548 全绿**，analyze 零 issue。
**发布**：`1.0.15+16`，`f686c65` 功能 → `eced07b` 发布；Gitee 四附件 + 仓库内清单 1.0.15/16 ✅、
GitHub draft=false 四附件一致 ✅、两源匿名下载抽查通过 ✅。

「班级名单」里改的、是不是改的**班名**、以及重启 App 后是否变正常。
