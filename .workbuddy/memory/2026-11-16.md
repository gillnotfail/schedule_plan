## 踩到的两个真 bug（都已锁进测试）
1. **`INSERT OR REPLACE` 在 SQLite 里是先 DELETE 再 INSERT**，会触发外键动作：
   - 覆盖 `class` → 级联删掉该班已排的 `lesson`、`student`（用户只想恢复班级名单，课表空了）；
   - 覆盖 `schedule_template` → 被 `class.template_id ON DELETE RESTRICT` 挡回
     （实测"同一个库上连恢复两次"就报 `FOREIGN KEY constraint failed`）。
   → 改成一律 **先 UPDATE、更新不到才 INSERT**。回归测试：
   「只恢复班级名单，不会顺带删掉已排的课」。
2. **`implied` 只判了 `!_selected.contains(slice)`**：清空全选后每一行都被当成"已包含"，
   变成 `onChanged: null` 点不动 → 用户再也勾不回来。必须
   `resolved.contains(slice) && !_selected.contains(slice)`。widget 测试第 3 条守住。

## 其他坑
- `PackageInfo.fromPlatform()` 在 widget 测试里会**挂住不返回**（pumpAndSettle 超时）。
  把它挪进 `BackupService.appVersion()`，测试替身覆写掉即可。
- `library;` 指令必须在 import **之前**，放到 import 之后会直接编译失败。
- file_picker 13 的 `saveFile` 签名是 `{fileName, bytes, mimeType, dialogTitle}` → `Future<Uri?>`；
  单个文件选择用 `pickFile`（返回 `PlatformFile?`），不是 `pickFiles`。
