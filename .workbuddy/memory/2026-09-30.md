## 需求（用户原话要点）

- 学生一旦点成休学或免修后就改不回来（bug）。
- 休学确实不大会来：排到最后没问题；但**再点这个学生的状态应弹「该学生已休学，是否复学」**，选复学→恢复，否则取消。
- 免修可能回来上课、也可能迟到早退：免修应**支持多个状态 / 多选**（即免修不是排他的，日常点名照常）。

## 结论与方案（第 16 轮定稿）

**休学 ≠ 免修**：

- **休学（suspended）= 完全不来**：锁死日常五态**与免修胶囊**；唯一出口是再点休学胶囊 → 「复学」确认
  （`attendanceResumeTitle/Body/Confirm`，非 danger 按钮，confirmLabel=复学）。
- **免修（exempt）= 免修这门课但仍会来**：**只作角标、不锁**；迟到早退照常标；免修与日常状态可同时高亮。

## 发布 v1.0.1（首个走完整链路 + 分差补丁的正式版本）

`pubspec.yaml` 1.0.0+1 → **1.0.1+2**；tag `v1.0.1` → 提交 `f976d45`；Release 4 个附件（2 整包 + 2 补丁）。
远端 main 已推，`updates/latest.json` 已入库 → 应用内「检查更新」现在能真正看到 v1.0.1。

**踩到并修掉的两个 `tool/release.py` 缺陷**（都是第一次真跑构建才暴露）：

1. `run(["flutter", ...])` → `FileNotFoundError [WinError 2]`。根因：Windows 的 flutter 是 `flutter.bat`，
   而 `subprocess` 走 `CreateProcess`，它只自动补 `.exe`（`PATHEXT` 是 cmd.exe 的规则）。
   → 新增 `flutter_command()`，用 `shutil.which("flutter")` 解析真路径。**手敲 `flutter` 能跑不等于脚本里能跑。**
2. `write_version` 的正则 `^version:\s*...\s*$` 里 **`\s` 会吃掉行尾换行** → 每次发版都静默删掉
   `version:` 与 `environment:` 之间的空行（pubspec 出现无意义 diff）。→ 改用 `[ \t]*$`；`read_version` 同步改。

**还踩了一个工具层的坑**：外层工具默认 120s 就掐，**`run_in_background` 并不豁免**。
第一次跑 release.py 时 `Duration: 2m 1s` 被杀，日志停在 `$ ... flutter.BAT build apk --release` 那一行
（`subprocess.run` 是 `capture_output=True`，构建期间不输出任何日志 → 看起来像卡住）。
→ 最终拆成两步：带 `timeout: 600000` 先 `flutter build apk --release`（~1m56s），
再用 `release.py --no-bump --no-build --push` 发布。

**分差实测（真实功能更新，非合成用例）**：

| ABI | 复用率 | 补丁 | 占整包 |
| --- | --- | --- | --- |
| arm64-v8a | 59.3% | 3.81 MB | **16.5%** |
| armeabi-v7a | 50.7% | 4.22 MB | **20.0%** |

→ 老师手机上升级只需下 **1/6 ~ 1/5** 的流量。对比合成用例「改 1 字节 = 99.9% 复用」差距很大，
**说明真实代码改动会让 `libapp.so` 大面积位移**，别用合成数字预期真实效果。

**一个容易误判的点**：v1.0.1 与 v1.0.0 的两个 APK **逐字节同大小**（`libapp.so` 刚好对齐），
但 sha256 不同。验证「有没有真重建」要比 **zip 内部条目的 CRC**（`AndroidManifest.xml` + `lib/*/libapp.so` 都变了）。
