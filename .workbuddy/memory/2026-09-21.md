## 1) Windows 桌面 `database factory not initialized`

修法：
- pubspec：把 `sqflite_common_ffi` + `sqlite3_flutter_libs` 从 dev_dependencies 移到 **dependencies**（运行时也要，APK 用系统 SQLite 不受影响）。
- `app_database.dart`：新增 `_ensureDatabaseFactory()`，按 `Platform.isWindows/isLinux/isMacOS` 初始化 FFI（幂等 `_ffiReady` 标记），再 `openDatabase`。
- **坑**：`sqflite_common_ffi` 重导出 `DatabaseException`，和 `app_exceptions.dart` 的同名类冲突 → 给 ffi import 加 `hide DatabaseException`；且 ffi 已含 sqflite 全部 API，**删掉**单独的 `sqflite` import（analyzer 判 unnecessary）。

# 第 11 轮：拍照识别课表（本机离线 OCR，不接 AI / LLM 服务商）

## 用户问题
"能否调用手机本身的计算能力或者功能，比方说 ocr 识图。用户拍照课表，自动识别，
自动生成课表。不需要 ai 或者 llm 提供商？"

## 结论
**可以，全程离线、零 API Key、零按次计费、照片不出设备。** 路线：
`手机相机/相册 → 本机 OCR（认字+包围盒） → 本地几何规则还原表格 → SQLite 落库`

关键判断依据：**课表是结构化表格**（字少字大、表头规整"周一…周五"/"第 N 节"），
这种场景"文字识别 + 坐标聚类"就够还原，不需要语言模型理解语义。

## 新增文件
- `lib/data/services/schedule_ocr_types.dart`：`OcrLessonDraft` / `ScheduleOcrResult`
  （独立文件，让解析层不依赖任何插件）。
- `lib/data/services/schedule_ocr_parser.dart`：**纯 Dart 解析层，本轮的核心资产**。
- `lib/data/services/schedule_ocr_service.dart`：引擎层，**可插拔后端**
  （`OcrRecognizer` 接口 + 默认 `UnavailableOcrRecognizer`）。
- `lib/data/services/schedule_ocr_import_service.dart`：草稿 → 课程 + 课表落库。
- `lib/features/management/course_ocr_page.dart`：三步流程页（选图 / 框选 / 核对）。
- `lib/features/management/crop_selector.dart`：`CropSelector` 框选控件（公开，有测试）。
- 测试：`test/unit/schedule_ocr_parser_test.dart`（17 例）、
  `test/widget/crop_selector_test.dart`。

## 解析算法（`ScheduleOcrParser.parse`）
1. 周几行 → 列锚点（中心 x），**按最长别名判定**；
2. 节次行 → 行锚点（中心 y），时间段可同行也可单独一行，就近挂到行锚点上；
3. 内容行 → 最近列 + **中点分界**定行（对不均匀行高宽容）；
4. 同格多行按 y 拼成课程名；抽出 `@教室` / `(101)` / `101室`。
`analyze` 只结构化（confidence = -1），`parse` 另给 0~100 启发式信心分。

## 引擎接入状态（重要）
本工程 `pubspec.yaml` **只加了 `image_picker`（取图）**，没加任何 OCR 插件。
真要启用识别：加 `google_mlkit_text_recognition`（Android，完全离线）
或 `apple_vision`（iOS，系统自带），实现一个 `OcrRecognizer` 后
`ScheduleOcrService.setupRecognizer(...)` 注入即可，**解析规则一行不用改**。
未接入时页面会弹「无法调用识别引擎」说明 + 替代方案（Excel 导入），不白屏不崩。

## 踩坑（都是真踩过的）
- **buckets 键序**：`buckets.putIfAbsent(row.index).putIfAbsent(column.index)`
  的键序是 **[节次][周几]**，组装时按 `buckets[weekday][period]` 读会把
  「第 2 节」写成「第 1 节」。教训：嵌套 Map 一定要把键序写进注释。
- **Dart 字符串插值 `$a.b`** 等价于 `${a}.b`，调试打印 `"$column.index"` 输出
  `Instance of '_Anchor'.index` —— 调试时用 `${column.index}`。
- **节次识别别吞时间段数字**：`08:50-09:30` 里的 50/09/30 会被裸数字规则吃成节次。
  先 `replaceAll(_timeRangePattern, ' ')` 再判，且裸数字只认"整行就是数字"。
- **噪声词别把真课滤掉**：`早读 / 自习 / 晚自习 / 升旗` 在国内课表里是**真占一节**的条目，
  不能进 `_noiseWords`（第一版放进去了，测试直接抓出来）。
- **首尾锚点外不要硬丢**：OCR 包围盒常比表格行窄，第一格文字的 y 中心可能比
  「第1节」表头还高几个像素 → `_rowFor` 首尾各留"半行"容差。
- **框选控件坐标变换**：图片 `contain` 铺进可用空间，屏幕像素与图片比例差一个
  缩放系数，所有指针事件都要过这个变换，否则手指和框错位（已写进测试）。
- `dart:ui` 的 `ClipOp` 不能裸用（`material.dart` 不导出），要么 `as ui` 前缀，
  要么用 `canvas.clipRect` + `ClipOp.difference` 时补 `import 'dart:ui' as ui`。

## 一、节假日/调休数据层（本轮最大的一块）

**核心认知：两个正交维度。** `DateTime.weekday`（天然星期几，永不变）和「国家安排的
放假/上班属性」是两件事，**不能合并**。周六调休上班正是两维不一致的产物。
所以引入 `CalendarDayKind { workday, weekend, holiday, makeupWorkday }`，
所有"这天休息吗"的判断必须查 kind，**禁止只判 `weekday == 6 || 7`**（会把调休上班的周六
当休息日，课时直接算少）。

**为什么必须内置而不能联网取**：`china_holiday_calendar.dart` 是静态表，
数据来源是国办年度通知**逐条抄录**（2025 = 国办发明电〔2024〕12 号；2026 = 2025-11-04 发布）。
理由写进了文件头注释：**联网请求日历服务会泄露"手机何时被打开过"**。
已覆盖 2025 / 2026（`coveredYears`，61 个放假日、11 个补班日），查不到时回落"周六日休息"，
表外年份走 `holidayOutsideCoverage` 提示，别让用户以为是 bug。加新年度 = 抄新通知，不写算法猜。

**「上周几的课」必须由老师确认，不能猜**：国务院只规定哪天上班，**没说补班那天上星期几的课**
（各校通知不同）。所以 `HolidayService.labelWeekdayOf` 里**只有 `makeupWorkday` 才允许被覆盖值改**，
其余一律返回天然 weekday。存 `app_settings.holiday_shift_YYYY-MM-DD`（`'1'..'7'` 或空串 = 不调整），
`holidayLastShift` 记住上次选择做弹层预选。总开关 `holidayAwareEnabled` 默认开，
关掉后提示与着色退场但**已确认的映射不清空**。

**`todayMakeupWorkday()` 必须先查开关、再看 dayOf 结论**——否则开关关掉还弹假提醒。

**课时结算改为按日历**：`TeachingInsightService.load()` 先取 `weekOf(weekStart)`，按 `lesson.weekday`
分桶，然后遍历这一周的真实日子：`if (!day.hasClasses) continue;` 只看 `day.labelWeekday` 那一桶。
即**放假不计、调休上班日按 labelWeekday 取课表**。`HolidayWeek.hasAdjustment` 只认
`holiday`/`makeupWorkday`（普通周末不算调整，否则每个周末都挂调休条）。

新增文件：`data/models/china_holiday.dart`（`CalendarDayKind` / `HolidayName` / `ChinaHoliday` /
`HolidayDay`(带 `isShifted`) / `HolidayWeek`）、`data/services/china_holiday_calendar.dart`（静态表）、
`data/services/holiday_service.dart`（静态表 + 老师确认映射的缝合层，带 `_enabledCache`）、
`features/toolbox/holiday_shift_sheet.dart`（七 chip + 「不调整」chip）。
`HolidayShiftChoice{final int? weekday;}` 是为了区分"取消"（返回 null）与"不调整"（返回 `HolidayShiftChoice(null)`）。

## 二、工具箱彩色功能卡

`ToolCardTone`（`core/theme/app_colors.dart`，`@immutable`，`key`/`light`/`deep` +
`gradientFor(Brightness)`，暗色下向白 lerp 0.10/0.06 提亮）。六色定稿：
`blue #446DC6/#34569F`、`violet #7E60BB/#61459C`、`rose #C04A74/#9E355C`、

## 踩坑
- **`await` 不能写在弹层参数里**：`suggestWeekday: await _holidays.lastShift()` 让 analyzer 报
  `use_build_context_synchronously`（schedule_page / calendar_page 各一处）。
  必须先 `final x = await ...; if (!mounted) return;` 再弹层。
- **假期里的周六不是 weekend**：`2026-09-26` 是周六但落在中秋假期（9/25–9/27）内，
  测试断言成 `weekend` 直接失败。这类日子最容易被写错，断言日期属性前先想清楚。
- **`dart:math` 的 `math.pow` 才是准的**：为算相对亮度手写 Taylor 展开，色板明度算错了两轮，
  换成 `math.pow(...).toDouble()` 才对。
- **`badgeColor ?? scheme.onSurfaceVariant` 触发 dead_null_aware**：改成
  `final labelColor = badge == null ? scheme.onSurfaceVariant : badgeColor;`。
  同一次 Edit 还把 `Text(` 误改成 `Text(\n Text(` 造成 dead_code —— 一次改两处容易连带出错。
- **`AppRadii.mediumAll` / `AppConstants.animationFast` / `buttonHeight` 都不存在**，
  正确写法是 `AppRadii.innerAll`、`AppMotion.quick`、`Size(0, 48)`。
- **改了 `_InsightSection` 的字段但调用处还传 `id:`**（4 处）→ 用 Python 脚本正则删行，
  不要手动一个个改。
- **PowerShell 重定向的正确写法是 `2>&1 | Out-File -Encoding utf8`**，读日志用
  `open(p, encoding='utf-8')`。之前记的 `*>` + UTF-16LE 那条已修正到 MEMORY.md。
