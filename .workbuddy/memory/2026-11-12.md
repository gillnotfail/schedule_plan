## 第 29 轮：考勤「迟到 + 早退」组合态

**用户规格**：除了休学 / 请假，其他学生的状态是「正常出勤 / 迟到 / 早退 / 同时迟到早退」——
迟到与早退要能同时选（尤其一节课点名两次的情况）。统计上同一名学生两种状态
**只算一次异常**，但两种状态都记着，方便老师定位、及时干预。

**为什么不做「第八枚迟早胶囊」**：第一版我按"一个状态一枚胶囊"做了第八枚，用户当场否掉 ——
"单独叫一个胶囊，臃肿且复杂。直接迟到和早退可以 and，而不是 or"。**胶囊数不能再涨**（行内已经有 7 枚、
姓名列本来就紧）。所以：**七枚胶囊不变，迟到 / 早退两枚可以同时点亮**，落库时合成一个值。

**交互约定（都写进了 `AttendanceStatusStrip._pick` 的注释）**：
- 点「迟」/「早」= **加上**这一头（`late || hasLate`），不是替换 → 点完迟到再点早退得到组合态，迟到不会被顶掉；
- 已亮的那一枚再点 = 减掉这一头；**只有组合态才允许从胶囊上减**（→ 只剩另一头），
  **单迟到再点「迟」不写库**（只回传原状态，页面按"同状态再点"给一次触觉）——
  手指抖一下就把异常抹成出勤，代价太大，要恢复出勤得显式点「出」；
- 出勤 / 缺勤 / 请假仍是单选，点它们把迟到早退一起清掉。

**关键取舍**：
- 组合态是**一个枚举值** `lateAndEarly`（库内键 `late_early`），不是两条记录 →
  `attendance_record` 唯一键 `(student_id, lesson_id, date)` 不变，**数据库零迁移**、
  `DatabaseSchema.version` 没动；
- 合成逻辑收在 `AttendanceStatus.fromLateEarly(late:, earlyLeave:)` 里（纯函数，可单测）；
- `choices` **保持 7 枚**（不含组合态），摘要改为遍历 `AttendanceStatus.values`
  （枚举声明顺序就是报表顺序）—— 照 `choices` 遍历会把"既迟又早"的学生整段漏掉，这条写在类注释里；
- `isAbnormal` 不改 → 组合态只算一次异常（记录条数口径）；
- 新增 `isLate` / `isEarlyLeave` 两个 getter，组合态在两个口径里都算 →
  `riskRanking` 的 SQL 用 `IN ('late','late_early')` / `IN ('early_leave','late_early')`；
- 摘要出一段「迟到+早退：1人，班级：姓名」，同一个人不会被报两遍；
- 胶囊宽度回到 27、`attendanceStatusChoiceCount` 回到 7（strip 205px，姓名列不吃亏）；
- `_StatusChip` 保留按字数缩字号（1 字 11.5 / 2 字 10 / 3 字 8.8），英文 "EL"/"Sus" 受益；
  「迟到+早退」不再有胶囊，但 `statusShortLabelOf` 的 switch 仍需给它一个短名（`迟早`，只备不显）。

**新增语义色** `lateAndEarly`：亮色 `#B4488F`（迟到橙与早退紫的中间色，白字对比度 4.9:1）、
暗色 `#E58FCB`；只在 `statusColorOf` 里用（行内没有它的胶囊），不进主题色漂移。

**门禁**：`analyze` 零 issue；`test` **+497**（组合态相关 7 条：and 语义 / 两枚同亮 / 减一头 /
单迟到不抹平 / 出缺假单选 / `fromLateEarly` 四组合 / 摘要只出现一次 + 仓储排名两个计数各一次）。
`l10n` zh/en 各 **723** 键。

## 第 30 轮：统计拓展 —— 「两本台账」（只写了 SPEC，未写代码）

**用户需求**：① 选区间 + 选学生 → 拉出这个学生每次课的出勤流水；② 选区间 + 选班级 →
班里所有人的出勤率排一张表，作为**给分依据**。二者一体，属于统计拓展，要能导出。

**调研结论（成熟产品）**：PowerSchool eSchoolPlus 把同一份数据做成
`Trends by Period/Course (Detail/Summary)` + `Student Detail Register`——「按人/按课」×「明细/汇总」
是两条正交轴，不是四个功能；Veracross Beacon / WISEdash 是「概览 → 风险名单 → 学生档案」三层下钻；
Borderset 强调月均出勤率是滞后指标，能驱动行动的是滚动窗口 + 新增越线的人；
希沃班级优化大师最贴近本场景（单个老师、无校级系统、档案可导出成册）。

**查出三个真实口径问题（重要，改动前必看）**：
1. `attendanceRateByCourse` 的出勤率 = `present 行数 ÷ COUNT(*)`，而**未标记的学生根本不落行**
   （界面只把未标记显示成"出勤"，`_effectiveStatus` 的默认值）。所以"只标了 2 个缺勤"的一节课
   会算成 **0%**（present=0 ÷ 2 行）。数字取决于老师标了几行，不是来了几个人。
2. 分母只含点过名的课次 → 漏点名的课次直接消失，出勤率偏高，且分不清"没点名"与"没人缺"。
3. 「异常明细」SQL 是 `status <> 'present'`（含请假），而 `riskRanking` 只算 缺/迟/早 ——
   同一页面上下两张表对"异常"的定义不一致。休学/免修走 `student_course_status`、不落记录，所以不在明细里。

**用户拍板的口径**：出勤率 = **1 − 缺勤课次 ÷ 应上课次**（举例 18 周 × 2 节 = 36，缺 5 → 86.1%）。
迟到、早退、**请假都不扣**；请假单列。应上课次按**当前课表推算、未点名按全勤**；
休学期间不计入应上、免修照常计入。改课表会追溯重算出勤率 —— 这条硬伤**必须写在界面上**。

**架构决定**：不新增业务表，`attendance_record` 已有 date/weekday/period_index/start/end/
course_name/class_name/status/note 全套快照 → 一条"台账查询" + Dart 纯函数聚合即可
（排行 = 按人分组，档案 = 按日期分组）。`DatabaseSchema.version` 仍为 9。

**两本台账**（用户原话："同一套数据，两本台账"）：
- 干预台账 = 现有 3.4 高风险排名（加权分），回答"该找谁谈" → **不动**；迟到/早退计数**含**组合态。
- 评价台账 = 新增 3.8 档案 + 3.9 班级排行，回答"分怎么给" → 五个状态数**互斥**（组合态单独一个数），
  能加总、能核对。**两者口径不同是刻意的，不要合并**。

**已写进 `docs/SPEC.md`**：3.1 加口径引用；3.6 扩到五个 Sheet；新增 3.7 时间区间与筛选
（本周/本月/本学期/自定义，默认本学期，补上班级维度，废掉写死的 90 天）、3.8 学生出勤档案
（汇总条 + 按状态分五组的流水表，默认只列异常、可切全部）、3.9 班级出勤率排行（按出勤率升序）、
3.10 考勤率怎么算（界面上要出现的文案，五条，含"改课表会重算"）、3.11 两本台账；
模块六新增 6.5 学生名单入口（行尾「出勤」，**整行点击仍是编辑**，不顶掉现有编辑路径）。
